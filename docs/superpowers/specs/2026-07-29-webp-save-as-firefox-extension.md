# Turn report — WebP → JPG/PNG Firefox extension

**Date:** 2026-07-29
**Working directory:** `F:\firefox plugin` (empty at session start)
**Request:** a Firefox plugin that adds a right-click option to save a WebP document as JPG/PNG,
converting automatically for download.

## What was built

A complete, loadable Firefox extension (MV2, Firefox 140+), 13 files in the shipped package,
26 KB packaged.

```
manifest.json          MV2, <all_urls> + menus/downloads/storage/notifications
manifest.v3.json       working MV3 variant (not the default — see "MV2 vs MV3")

src/lib/sniff.js       magic-byte format detection (11 formats, WebP variants in detail)
src/lib/convert.js     createImageBitmap → OffscreenCanvas → convertToBlob, with fallbacks
src/lib/filename.js    output filename derivation and filesystem sanitising
src/lib/settings.js    validated defaults over storage.local
src/lib/pagefetch.js   in-page fetch for blob: URLs
src/options/*          settings UI (11 controls, light/dark)
icons/*.svg            extension + per-menu-item icons
scripts/package.ps1    builds dist/*.xpi, validates the archive
```

## Decisions that shaped it

**Bytes over filenames.** The obvious implementation filters the menu with
`targetUrlPatterns: ["*://*/*.webp"]`. That misses the common case — CDNs serve WebP from `.jpg`
addresses with `image/jpeg` headers. Instead `menus.onShown` identifies the image (URL shortcut →
cache → 64-byte sniff), then `menus.refresh()` repaints the open menu. The sniff uses
`cache: "force-cache"` and cancels the response stream after 64 bytes, so it normally costs no
network at all. There is now a passing test for exactly this case.

**MV2, not MV3.** Firefox MV3 does not grant host permissions at install time, and this extension
cannot read image bytes without them — under MV3 every conversion fails until the user hunts down
the permission. MV2 is still fully supported (verified: it installs and activates on Firefox 154).
The MV3 variant ships alongside for whenever that changes.

**Unidentified images still get the menu.** Hiding the feature whenever detection fails produces
a worse bug than offering it and reporting a real error. `hideWhenUnknown` inverts this for anyone
who prefers strict behaviour.

**JPEG gets an explicit background fill.** Without it transparent WebP pixels come out black.
Only `#rgb`/`#rrggbb` is accepted because an invalid `fillStyle` assignment fails *silently* —
which would leave the canvas default (black) and look like a conversion bug.

## Verification

Three tiers, 90 checks, all green.

| Tier | What runs it | Checks |
| --- | --- | --- |
| Pure logic | `node --test`, no browser | 64 |
| Conversion in Gecko | headless Firefox 154 + local HTTP server | 12 |
| The installed extension | packaged xpi sideloaded into a throwaway profile | 14 |

Plus `web-ext lint`: **0 errors, 0 warnings, 0 notices**.

The third tier is the one that matters most: it packages the add-on, sideloads it, and runs a test
page *inside the extension* that reaches the real background page. It confirms permissions were
actually granted, the menus API accepts the item definitions (SVG icons included), the 12-case
show/hide matrix, a WebP disguised as `image/jpeg` behind a `.jpg` name, the `blob:` fallback
(having first proved the background page genuinely cannot read that URL), the options page
round-tripping through `storage.local`, and a converted JPEG landing on disk — which the runner
then re-opens and verifies byte for byte (30,394 bytes, starts `ff d8 ff`).

Fixtures are real: a 2,358-byte lossy WebP from disk, plus a VP8X-with-alpha and a VP8L-lossless
file generated by Firefox's own encoder during the harness run. Their headers were hand-decoded
(`flags 0x10`, canvas `0x27+1 × 0x17+1`; bitfield `0x1005c027` → 40×24 + alpha) so the assertions
rest on independently derived ground truth rather than on the parser's own output.

### Mutation testing

15 mutations were injected one at a time; **14 were caught immediately, 1 survived**:

> `WEBP_FLAG_ANIMATION 0x02 → 0x04` survived, because the test fed the exported constant back as
> its own input. A circular assertion that could never fail.

Fixed by hard-coding the spec literals in the test inputs and pinning the constants in a separate
assertion. Both flag mutations are now caught. Two further mutations were run against the browser
tiers (skip the JPEG background fill; stop sniffing bytes in `identify()`) — both caught.

## Bugs found and fixed during the work

1. **Character-class regex silently wrong.** The filename sanitiser's invalid-character class was
   written as a literal range from space to `<`, which would have stripped digits and punctuation
   from every filename. Rewritten with `\u` escapes; the file now contains no raw control bytes.
2. **Windows paths not split on backslashes** — `C:\Users\me\pic.webp` became `Users me pic.jpg`.
   Caught by a unit test, fixed in `basenameFromUrl`.
3. **2-byte signatures rejected** by a 3-byte minimum-length guard, so a raw JPEG XL codestream
   was unidentifiable. Lowered to 2.
4. **The .xpi was built with backslash path separators.** `ZipFile.CreateFromDirectory` on .NET
   Framework writes `src\lib\convert.js` as the entry name, which is not a valid zip path. Caught
   by validation inside the packaging script itself; entries are now added explicitly.
5. **`npm test` was launching Firefox.** `node --test` with no arguments treats every `.js` under
   `test/` as a test file, so the browser runners and the in-extension scripts were being executed
   as unit tests (2 failing). Now scoped to `test/*.test.mjs`.
6. **AMO-required manifest key missing.** `web-ext lint` flagged
   `data_collection_permissions`; adding it then flagged a min-version conflict (needs Firefox 140
   desktop / 142 Android). Resolved with `strict_min_version` 140 plus a `gecko_android` block.

## Known gaps

- **The context menu appearing has not been automated** — nothing can script Firefox's native
  context menu. Everything around it is tested (Firefox accepts the definitions, `onShown` and
  `refresh` exist, the decision logic is covered across 12 cases). One human right-click is still
  needed to confirm the item renders as expected.
- Animated WebP yields the first frame only, detected and reported.
- SVG/TIFF/JXL/HEIC are deliberately not offered — Gecko cannot re-encode them via canvas.
- Notifications are wired but not asserted in any test.
- The package is unsigned, so release/ESR Firefox needs `about:debugging` or AMO signing.
